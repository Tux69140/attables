# Refonte UI 0.3.0 — plan de mise en œuvre

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** livrer Attablés 0.3.0 : premier lancement guidé, palette Safran + olive / Nuit marine, pictogrammes Lucide, allergies sous une seule forme toujours visible, écran Invitations à onglets, écran Convives foyers/individuels, onglet Plats avec allergènes et alertes.

**Architecture :** tout reste dans le frontend React (état unique `AppData` dans `App.tsx`). La logique nouvelle vit dans des fonctions pures testées (`src/utils/*.ts`) ; les écrans les consomment. Les icônes sont des SVG recopiés dans le dépôt, nettoyés et convertis en données TypeScript par un script, partagés par l'appli et le site.

**Tech Stack :** React 19, Vite, Tailwind v4, TypeScript, `node:test` + `tsx`, Tauri v2 (Android), pnpm.

**Spec :** `docs/superpowers/specs/2026-11-17-refonte-ui-premier-lancement-design.md` (citée « §x.y » ci-dessous ; les valeurs exactes y sont, le plan ne les recopie que lorsqu'un test en dépend).

**Branche :** travailler sur `refonte-ui-0.3.0` créée depuis `main` (ne pas commiter sur `main`). Un commit par tâche.

## Global Constraints

- Aucune nouvelle dépendance (ni `lucide-react`, ni `lucide-static` à l'exécution), aucun réseau, aucune télémétrie ; pnpm uniquement, pas de `package-lock.json`.
- Couleurs uniquement via les variables de `src/index.css` (`:root` clair, `.dark` sombre), valeurs du §5.1.
- Contraste WCAG AA : texte ≥ 4,5:1 ; texte large ou gras ≥ 14 px ≥ 3:1.
- Le rouge `--alerte` (`#B42318`, texte blanc) est réservé aux allergies strictes ; aucune autre couleur rouge, orange ou terracotta d'accent.
- Le bouton flottant porte toujours un texte.
- Toute vue plein écran, modale ou feuille utilise `useAndroidBack`.
- Toute action destructrice : snapshot de `data` + `showUndo(message, snapshot)` (7 s).
- Tout nouveau champ de `AppData` est normalisé dans `migrateAndValidateAppData` ; `CURRENT_DATA_VERSION` reste à 1 (ajouts seulement).
- Pas de dictionnaire de plats : rapprochement par `normalizeForCompare` (casse, accents, espaces, œ/æ, apostrophes, tirets) + suggestion « Vous voulez dire… ? », jamais de fusion automatique.
- `MODE_DEMO` : jamais d'écriture dans `localStorage`, thème clair forcé, pas d'accueil (porte « exemples » directe).
- En-tête copyright/SPDX GPL-3.0-or-later (format des fichiers existants) sur tout nouveau fichier source ; mention ISC pour les SVG Lucide.
- Textes de l'interface en français, apostrophe typographique `’`, espaces insécables avant `; : ! ?` et dans `« »`, comme le code actuel.
- Pages légales du site (`site/{mentions-legales,confidentialite,conditions-utilisation}.html`) : ne pas les éditer.
- Validation de chaque tâche : `pnpm lint`, `pnpm test`, `pnpm build`, puis contrôle dans le navigateur (`pnpm dev`, fenêtre 412 × 915, thème clair **et** sombre).

## Review Focus

1. **Saisie vide ou faite d'espaces** dans « Vérifier ou enregistrer un plat » : aucune proposition « + Enregistrer «  » », liste complète affichée. → Tâche 12.
2. **Invitation datée d'aujourd'hui** : libellé « aujourd’hui », considérée « à marquer » (pied « Le repas a eu lieu ? ») et triée en tête. → Tâche 8.
3. **Même plat écrit différemment** (« Tarte tatin », « tarte Tatin  », « TARTE TATIN », apostrophe `'` ou `’`, « Pot-au-feu » / « pot au feu ») : une seule entrée dans Plats, « Enregistrer » complète la fiche existante au lieu d'en créer une seconde. → Tâches 5 et 12.
4. **Suppression d'une contrainte personnalisée utilisée comme allergène d'un plat** : retirée des convives **et** des fiches de plat ; aucune référence pendante. → Tâche 5.
5. **Tablée avec beaucoup d'allergies strictes** (4 et plus) : le bandeau de carte reste sur une ligne, deux allergies puis « +n ». → Tâche 8.
